## 2026-11-14 11:55 — D2 → D1: Random Forest forecast — proposal (needs your OK + a `contract/` change)

Team decided to use a Random Forest for the next-month estimate. Note: the spec's "Do not" list says
"Add ML models" — we are overriding that on purpose; please confirm, and H2 should not claim otherwise in the pitch.

Proposal (API response shape **does not change**, so F1/F2 are not affected):
1. **D1 trains + predicts offline** in `pipeline/` (or a script you own); the api gets no ML runtime.
   Suggested features per 0.1° cell: calendar month, same-month baseline median (2003–2025), last 3 complete months'
   MEC, lat, lon. Train only on complete non-provisional months; hold out 2024–2025 like the calibration.
2. **New file `out/forecast_rf.json`** = list of `CellForecast{cell_id, target_month, expected_mec}`
   (one row per cell with any history; target_month = next month after the last complete month).
   Needs a new record `contract/.../data/CellForecast.java` — please agree the name/fields.
3. **Demo areas:** put RF p25/p75 (from the per-tree spread) into `demo/{area_id}.json` → `forecast.experimental`?
   That would add a `forecast` field to `DemoFile` (contract change) — alternative: D2 leaves p25/p75 `null` for RF.
   Your call.
4. **api (D2)** sums `expected_mec` of the cells inside the AOI → `experimental.expected_mec`,
   `method = "random_forest_v1"`, `scale_s = null`, p25/p75 null for non-demo AOIs.
   If `forecast_rf.json` is missing or fails to load, D2 falls back to the spec formula
   (`method = "baseline_median_x_recent_scale"`). Official SPC outlook stays a separate field (never blended).
5. **Optional, nice for the pitch:** report RF hold-out MAPE next to the plain baseline-formula MAPE
   (e.g. `forecast_rf_meta.json{method, holdout, mape, baseline_mape, n_cells}`) → D2 shows it in `/api/meta`.

## 2026-11-14 11:40 — D2 → D1: Maven skeleton + `contract/` draft ready for review

Built and tested (`./mvnw -pl contract test` → 14 tests pass). Needs JDK 21 (see README).
Package root `ie.ucd.spaceteam.firecal`. Pipeline module is only an empty picocli `Main` — it's yours.

Choices I made where the spec was silent — **please agree or change before we freeze**:
1. `parent` is an enum serialized as `United_States | Canada | Mexico` (FIRMS file-name spelling).
2. `calibration.train` and `validation.holdout` are `{"from": 2018, "to": 2023}` (`YearRange`).
3. `CalibrationFactor.month` is 1–12. For `country[]` rows `region_id` = country name; for `north_america[]`
   rows `region_id = "NA"` and `parent = null`. `level` = `region | country | north_america`.
4. `coverage.json`: `from` is a month (`"2002-07"`), `sp_until` is a date (`"2026-08-31"`).
5. `hotspots/*.csv`: `acq_time_utc` = `HH:MM`; `type` empty for NRT rows; `sensor` = `MODIS | VIIRS`;
   `satellite` = `Aqua | Terra | N20`. Column list is `HotspotRow.COLUMNS`.
6. `demo/{area_id}.json` = `{"calendar": <CalendarData>, "summary": <SummaryData>, "device": <DevicePayload>}`
   (the `data` parts only, no envelope).
7. `config/demo_areas.json` = list of `{area_id, name, country, bbox: [w, s, e, n]}`.
8. `FireJson.mapper()` fails on unknown fields and on null/missing numbers in primitive fields — so a missing
   `mec` in `cell_month.json` is a load error, never a silent 0.
